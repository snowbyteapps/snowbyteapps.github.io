Every meeting says “Busy”

You picked Full details, but the sign shows “Busy” on every row - no titles, no organisers. Almost always this means the calendar feed itself contains no detail. Here is how to confirm that in about a minute, and what to change.

Short version. Calendar systems can strip meeting details before publishing a feed. When that happens the detail never reaches RoomBoard, so no in-app setting can bring it back. The check below tells you whether that is what is happening.

Step 1 - Look at the feed itself

This is the only step that matters, because it settles the question without guessing. Open your calendar address in a normal browser tab - the same address you gave RoomBoard. Your browser will either display the file or download it; either is fine. Open it in any text editor.

You are looking for lines beginning SUMMARY:.

If you see real titles

e.g. SUMMARY:Q3 Budget Review - the detail is in the feed. RoomBoard should be showing it. Check Settings → Privacy is set to “Full details”, and note that meetings marked private in the calendar are always reduced to “Reserved” by design. If titles are present and still not showing, that is a genuine fault - please send us the details.

If every line says SUMMARY:Busy

The detail was removed before publishing. Nothing in RoomBoard can recover it - the words are not in the file. Continue below to find out which setting removed them.

While you are there, check whether ORGANIZER and LOCATION lines exist at all. A feed stripped to availability-only usually has neither.

Step 2 - Find which setting stripped it

There are two separate places detail can be lost, and they are independent - a room calendar can be affected by both at once.

A. The calendar was published as “busy only”

Most calendar systems let you choose how much a published link reveals. Choosing the availability-only option strips titles server-side.

  • Outlook / Microsoft 365: Settings → Calendar → Shared calendars → under “Publish a calendar”, the permission dropdown. “Can view when I'm busy” strips detail; “Can view all details” keeps it.
  • Google Calendar: Settings and sharing → “See all event details” rather than “See only free/busy”. Use the Secret address in iCal format.
  • Apple / iCloud: a public calendar link includes detail; there is no busy-only variant.

If “Can view all details” is greyed out or missing, you have hit an organisation-wide policy rather than a personal setting. In Microsoft 365 an administrator can cap how much detail anyone in the organisation may publish externally. No amount of retrying in Outlook will change it - it needs an administrator. See the note for administrators below.

After changing the permission you normally have to republish, and the address usually changes. Scan or paste the new one.

B. The room calendar deletes subjects when meetings are booked

This one catches people out, because it happens at booking time rather than publishing time. If your room is a resource mailbox - a calendar belonging to the room, which people invite rather than book directly - Microsoft Exchange deletes the meeting subject by default and replaces it with the organiser's name.

The consequence worth knowing: the subject was never stored on the room's calendar, so changing this only affects meetings booked afterwards. Existing bookings stay detail-free permanently. If you are testing, book a fresh meeting after changing it rather than waiting.

An administrator can check the current behaviour with:

Get-CalendarProcessing -Identity "Room Name" |
  Format-List DeleteSubject, AddOrganizerToSubject, DeleteComments

and keep subjects with:

Set-CalendarProcessing -Identity "Room Name" `
  -DeleteSubject $false -AddOrganizerToSubject $false

AddOrganizerToSubject prepends the organiser's name to the title. On a sign in a public corridor that means showing staff or guest names to passers-by, which is usually not what you want - hence $false.

For administrators

If your organisation caps published calendar detail, the tempting fix is to raise the limit for everyone. Consider not doing that: it would let any account publish full calendar detail to a public URL.

A narrower approach is to allow the higher detail level only for the room mailboxes that drive displays, leaving staff mailboxes restrictive. In Exchange Online that means a separate sharing policy assigned to those mailboxes rather than changing the default one. Check what is in place now before changing anything: 

Get-SharingPolicy | Format-List Name, Domains, Enabled, Default

Exact commands vary by tenant and Microsoft changes them over time. Treat the above as the shape of the problem rather than a script to paste - and check Microsoft's current documentation for your environment.

Is busy-only actually a problem?

Worth asking before changing any policy. The question a passer-by asks is “is this room free, and when does it free up?” - and a busy-only feed answers that completely. Times are correct, the status is correct, and “In Use · until 14:30” is exactly as useful as it would be with a title attached.

For a room in a public corridor, showing meeting subjects to everyone walking past is often the wrong choice anyway - which is why RoomBoard has Titles only and Busy only privacy modes of its own. If you were going to hide detail in the app, there is little reason to publish it in the first place.

Other things worth knowing

Meeting times are shifted by whole hours

RoomBoard shows times in the tablet's own timezone. If a meeting reads 14:00 on the sign and 15:00 in the calendar, set the tablet's timezone to match the room: Android Settings → System → Date & time, and prefer automatic network time.

Some meetings say “Reserved”

Meetings the calendar marks as private are always reduced to “Reserved”, whatever privacy mode you choose. That is deliberate - the organiser asked for privacy, so it is not treated as a preference. Note that the booking still appears: the room correctly shows as in use.

The sign shows “Showing saved schedule”

The tablet could not reach the calendar and is showing the last schedule it successfully loaded. It appears once the saved copy is old enough to possibly be out of date, and clears itself on the next successful refresh. If it stays, check the tablet's Wi-Fi and that the calendar address still works.

Testing the feed says the browser blocked it

That only happens in the web preview, where browsers block cross-origin requests to calendar servers. The same address works in the Android app - test it on the tablet.
